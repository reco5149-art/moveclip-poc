# AI 모델 선정 근거

문제정의서의 각 단계(A~F)에 어떤 모델을 왜 골랐는지, 다른 후보와 무엇이 달랐는지 기록한다.
**선택 기준은 세 가지였다 — ① 내 노트북(CPU)에서 돌아갈 것 ② 별도 API 키·비용 없이 재현 가능할 것 ③ 회원 영상을 외부로 보내지 않을 것(초상권).**

---

## 최종 구성

```
영상 ──┬─▶ [YOLO11n-pose] ──▶ 관절 17점 시계열 ──▶ [자기상관+피크검출] ──▶ 세트·반복
       │                                                    │
       └─▶ 오디오 ──▶ [Silero VAD] ──▶ [Whisper base ONNX] ──┴─▶ 하이라이트 점수
                                        │
                                        └─▶ [규칙기반 추출요약] ──▶ 카드뉴스·캡션
```

AI 모델 3개(YOLO11-pose / Silero VAD / Whisper)를 하나의 파이프라인으로 엮었다.

---

## 1. 자세 추출 — **YOLO11n-pose** 선택

| 후보 | 장점 | 탈락·선택 이유 |
|---|---|---|
| **YOLO11n-pose** ✅ | 6MB, CPU에서 74ms/프레임, 사람 검출+키포인트가 한 번에 | **선택.** 다인원이 나오는 그룹 수업 영상까지 같은 코드로 확장 가능 |
| MediaPipe Pose | 가볍고 정확, 3D 좌표 | 1명만 가정하는 설계라 그룹 수업 확장이 막힘. 현재 배포판(0.10.32)은 모델 파일을 런타임에 받아와야 해서 오프라인 재현성도 떨어짐 |
| OpenPose | 다인원 정확도 높음 | 빌드가 무겁고 GPU 전제. "내 노트북에서 돌아갈 것" 기준 탈락 |
| RTMPose | 정확도 최상위 | 모델 배포 경로가 복잡. PoC 단계에 과함 |
| **SAM (세그멘테이션)** | 인물 분리 품질 최고 | **메인 파이프라인에는 불필요.** 필요한 건 '관절 위치'지 '픽셀 마스크'가 아니다. 마스크를 뽑아도 반복 횟수는 못 센다 |

> 실측: 1280x720 영상 298프레임 분석에 30.4초, 인물 검출률 100%.

**세그멘테이션을 아예 안 쓴 건 아니다.** 검증용 합성 영상을 만들 때 인물을 배경에서 떼어내는 용도로 `YOLO11n-seg`를 썼다(`tools/make_sample.py`). SAM을 쓸 수도 있었지만 모델이 훨씬 크고, 이미 받아둔 YOLO 계열로 충분한 품질이 나와서 그대로 갔다.

## 2. 반복(rep) 검출 — **신호처리 (자기상관 + 피크검출)** 선택

| 후보 | 탈락·선택 이유 |
|---|---|
| **극값 검출(find_peaks) + 도메인 가중 신호 선택** ✅ | **선택.** 학습 데이터가 0건이어도 오늘 바로 동작. 어떤 관절 신호로 판정했는지 설명 가능(`signal` 필드) |
| RepNet 등 반복 카운팅 딥러닝 모델 | 사전학습 가중치 확보·환경 구성 비용이 큼. 틀렸을 때 이유를 알 수 없음 |
| 고정 임계값 규칙 (예: 무릎 140도 이하면 1회) | 종목마다 임계값을 다시 잡아야 함. 스쿼트·런지·버피가 섞인 실제 수업 영상에서 무너짐 |

**설계 포인트:** 무릎각·고관절각·팔꿈치각·골반높이·손목높이 5개 신호를 모두 만들어두고, **구간마다 쓸 신호를 자동으로 고른다.** 종목을 미리 지정하지 않아도 되는 이유다.

**신호 선택 기준을 실제 영상으로 한 번 갈아엎었다.** 처음에는 '가장 주기적인 신호'를 골랐는데, 실제 코칭 영상에서 반복 간격을 재보니 4.8~10.6초로 제멋대로였다 — 코치는 설명하느라 리듬이 깨진다. 운동 영상은 메트로놈이 아니다. 그래서 **가동범위 × 관절 우선순위**로 바꿨고, 상체 신호(팔꿈치·손목)는 가중치를 낮췄다. 코치가 말하면서 팔을 쓰는 게 오검출의 주범이었기 때문이다. 과정과 수치는 [검증 결과 3-2 ~ 3-4](03_validation.md) 참조.

## 3. 음성인식 — **Whisper base (ONNX, sherpa-onnx)** 선택

| 후보 | 탈락·선택 이유 |
|---|---|
| **Whisper base ONNX** ✅ | **선택.** 한국어 지원, 완전 로컬, API 비용 0원, CPU에서 실시간 대비 0.15배 속도 |
| Google/Clova STT API | 정확도는 높지만 **회원 목소리가 담긴 파일을 외부로 업로드**해야 함. 초상권·개인정보 문제로 탈락 |
| Vosk | 가볍지만 한국어 정확도가 Whisper보다 낮음 |
| faster-whisper | 더 빠르지만 모델 배포 경로 의존성이 있어 재현성이 떨어짐 |

> 실측: 참조 음성 23초를 4초에 처리(0.15x). `python tools/check_stt.py`로 재현 가능.

**모델 크기는 base → small로 올렸다.** 실제 코칭 영상의 원본 자막을 정답으로 문자오류율을 재보니:

| | 모델 크기 | 문자 정확도 | 107초 영상 처리 |
|---|---|---|---|
| whisper **base** | 200MB | 61% | 30초 |
| whisper **small** ✅ | 1.3GB | **71%** | 52초 |

base에서는 같은 음절을 무한 반복하는 디코딩 붕괴("2.5.5.5.5.5…")까지 나왔는데 small에서는 사라졌다.
**다만 71%도 목표(수정률 20% 이하)에는 못 미친다.** 운동 도메인 고유명사가 특히 약하다 — "크로스핏"→"크스", "플레이트"→"플이트". 다음 단계는 medium 시험과 도메인 용어 사전 확장이다.

## 4. 음성 구간 검출 — **Silero VAD** 선택

Whisper는 30초 창 단위라 40분짜리 영상을 통째로 넣을 수 없다. 침묵까지 전부 디코딩하면 시간 낭비이기도 하다.
에너지 임계값 방식은 체육관 소음(음악, 기구 소리)에 그대로 뚫린다. **Silero VAD는 1.7MB짜리 모델로 '사람 목소리'만 골라낸다** — 체육관 환경에서 이 차이가 크다.

## 5. 카드뉴스 문구 — **규칙 기반 추출 요약** 선택 (생성형 모델 배제)

| 후보 | 탈락·선택 이유 |
|---|---|
| **추출 요약 (도메인 키워드 + 어미 패턴)** ✅ | **선택.** 내가 실제로 한 말만 카드에 올라간다 |
| LLM 생성 요약 | 문장은 매끄럽지만 **내가 하지 않은 코칭 멘트를 지어낼 수 있다.** 통증·운동 지도는 잘못된 문장 하나가 신뢰를 무너뜨리는 영역이라 배제 |
| Diffusion 이미지 생성 | 카드 배경을 생성할 수도 있었으나, **실제 회원·현장 사진이 있는데 AI 이미지를 쓸 이유가 없다.** 영상에서 뽑은 실제 프레임을 배경으로 사용 |

점수식: 도메인 키워드 포함(무릎·호흡·코어 등 47개) + 지시형 어미(~하세요/~보세요) + 카드에 얹기 좋은 길이(12~45자).

---

## 정리 — 이 조합을 고른 한 문장

> **"GPU 없이, API 비용 없이, 회원 영상을 밖으로 내보내지 않고, 틀렸을 때 왜 틀렸는지 설명할 수 있는 조합."**

정확도 최상위 모델을 고르는 문제가 아니라, **1인 트레이너가 자기 노트북에서 매주 돌릴 수 있느냐**가 이 프로젝트의 제약이었다.
